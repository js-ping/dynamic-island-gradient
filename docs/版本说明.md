## v2.2.0 — 2026-10-13

**两件事：改名 + 正式支持 Windows。**

### 1. 改名：灵动岛渐变工具 → 岛影

| 理由 | 说明 |
|---|---|
| 短、好记 | 两个字，念得出、记得住，比「灵动岛渐变工具」更像一个产品名 |
| 有画面 | 「影」既是**阴影**（顶部那层渐变遮罩），也是**影像**（壁纸） |
| 有谐音 | **岛影 ≈ 倒影** —— 顶部暗部像水面投下的影子，灵动岛融进去就像本来就在照片里 |
| 少风险 | 不再把 Apple 的营销词「灵动岛」当名字主体，商标上更安全，辨识度反而更高 |

英文名沿用 **Dynamic Island Gradient**，仓库地址不变。

### 2. 正式支持 PC（Windows）

主程序本来就是网页，Windows 一直能跑。这一版把「能跑」变成「好跑」：

| 改动 | 说明 |
|---|---|
| `启动.bat` | Windows 双击入口。`.html` 被关联给记事本时，双击它照样用默认浏览器打开 |
| `docs/生成说明书.bat` | Windows 上重建说明书的入口 |
| 快捷键提示自适应 | 界面原来写死 `⌘V`，现在按系统显示：Windows/Linux 是 `Ctrl+V`，macOS 是 `⌘V` |
| 导出文件名改 ASCII | `DynamicIsland_...jpg` → `Daoying_...jpg` |
| `.gitattributes` | 锁定行尾：`.bat` 强制 CRLF，`.command`/`.sh` 保持 LF |
| README / 说明书 | 新增三系统对照表 + Windows 常见问题 |

> **两个 `.bat` 刻意写成纯 ASCII + CRLF。** 中文 Windows 默认代码页是 GBK，
> 批处理里写中文很容易变乱码。所有中文说明都放在 README 和内置说明书里。

## v2.0.0 — 2026-10-09

**关键词：** 从「能用」到「好用」的整轮重做。

### 这一版做了什么

原版的三个真问题：

1. **尺寸单位是死的。** 滑杆写死 60–200px / 200–600px，而一张 iPhone 壁纸高
   2868px —— 也就是说「完全覆盖 120px」在真实图上只盖住顶部 4% 都不到的一条缝，
   工具在真机上基本不可用。
2. **逐像素渲染会卡。** 1320×2868 ≈ 380 万像素，每次滑杆移动都跑一遍
   `getImageData` → 循环 → `putImageData`，拖动明显掉帧。
3. **预览只能左右分栏静态看**，看不出渐变到底过不过渡得自然。

v2 的对应处理：

| 问题 | v2 的做法 |
|---|---|
| 单位失真 | 全部改用**按图片高度计的百分比**，并实时换算显示像素值 |
| 渲染卡顿 | 改用 `createLinearGradient()` + 64 级色标，每次重绘只有两次 `drawImage` + 一次 `fillRect`，**原分辨率下拖动为实时** |
| 预览抽象 | **可拖动的分割线对比** + 宽屏时的**锁屏实机预览**（显示真实时间） |

顺带补上的：四种过渡曲线（带实时曲线图）、覆盖强度、快速预设、
灵动岛参考框、抗色带噪点、参数记忆、画质选择、剪贴板导入、
内置示例图、深浅色主题、移动端适配、文件名编码参数。

完整逐条改动见 [CHANGELOG.md](../CHANGELOG.md)。

### 交付形态

```

├── 使用说明.html          ← 图文说明书

├── 启动.command           ← 需要手机访问时双击
├── README.md / README.en.md / CHANGELOG.md / LICENSE
├── docs/
```

> **为什么没有 `程序/` `文档/` 分家？**
> 本工具是纯静态单文件，没有后端、没有依赖、没有运行时。
> 拆成多层目录只会让「下载一个文件就能用」这件事变复杂。
> 因此只把说明文档收进 `docs/`，其余保持根目录直给。

### 验收

无头 Chrome 自检通过，覆盖：

- 顶部纯色区像素 == 设定基色 `(8,10,12)`
- 「渐变结束高度」以下像素与原图**逐字节一致**
- 导出 blob 正常（JPEG，253 KB / 1320×2868）
- 桌面 1440px 与手机 390px 视口：均无横向溢出、无 JS 报错
- 说明书页面：8 个表格、8 个章节、8 条目录链接，桌面与移动端均无溢出

### 回滚

需要退回旧版，直接用 `~/Desktop/灵动岛渐变工具/`（v1 原样保留，未做任何改动）。
注意 v1 的滑杆单位是像素，在真机壁纸上不可用，仅作存档。

### 在线版待办

GitHub Pages 已在仓库上开启，构建状态 `built`。但**当前访问不通**，原因是一条链路错配：

```
js-ping.github.io/dynamic-island-gradient/
        ↓ 301（因为 js-ping.github.io 用户站设了自定义域名 uppjs.com）
uppjs.com/dynamic-island-gradient/
        ↓ 但 uppjs.com 的 DNS 实际指向腾讯云 EdgeOne，不是 GitHub Pages
404
```

`uppjs.com` → `www.uppjs.com.pages.dnsoe5.com` → `43.174.246.63 / 43.174.247.63`（腾讯云）。

**三条可选路径，选一条即可：**

1. **把本文件夹部署到 EdgeOne**，挂到 `uppjs.com/dynamic-island-gradient/` —— 与现有 `uppjs.com` 工具清单站同一套流程，最一致。
2. **去掉 `js-ping.github.io` 用户站的 CNAME**。GitHub Pages 会立刻恢复，项目页地址为
   `https://js-ping.github.io/dynamic-island-gradient/`；`uppjs.com` 不受影响（DNS 已经指向 EdgeOne）。
   代价是 `js-ping.github.io → uppjs.com` 这条跳转会失效。
3. **不做在线版**，仓库只作为源码分发。

在选定之前，README 里不放具体在线地址，避免给出会 404 的链接。

### 推送时踩到的坑（值得记住）

1. `/etc/hosts` 里有一段 WorkBuddy 注入的「GitHub Acceleration」映射，**把 `api.github.com`
   指到了 `github.com` 的 IP `20.205.243.166`**。后果是对 API 的任何请求都会被 GitHub 边缘
   301 到 `github.com/<path>`，看起来像「token 失效」或「被墙」，其实只是 IP 指错了。
   真实的 api.github.com 用 `140.82.114.6` / `20.205.243.168`。绕过方式：`curl --resolve api.github.com:443:140.82.114.6`
   并临时清掉 `HTTP(S)_PROXY` 环境变量。
2. WorkBuddy 的出口代理不放行 `api.github.com`，即使 hosts 修对了也要绕开代理。
3. **SSH（22 端口）一直是通的**，所以 `git push` 从来不是问题 —— 卡的只是「建仓库」这一步。
